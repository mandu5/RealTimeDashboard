## 🛠️ Engineering Challenges & Solutions

단순해 보이는 '모니터링' 시스템 구축 과정에서 수많은 기술적 난관들을 마주했습니다.

### 1. 스레드 안전성 (Thread Safety) - ⚡️ 동시성의 함정

가장 먼저 부딪힌 문제는 **"패킷은 계속 들어오는데, 처리가 늦어지면?"** 이었습니다.
Scapy의 `sniff` 함수는 블로킹 방식으로 동작하는데, 여기서 직접 DB에 쓰고 분석까지 하면 패킷 유실(Loss)이 발생할 수밖에 없었습니다.

**해결책**: **Producer-Consumer 패턴** 도입

- `PacketSniffer`(Producer)는 오직 패킷을 큐에 밀어넣기(`put`)만 수행.
- `PacketProcessor`(Consumer)가 별도 스레드에서 큐를 비우며 무거운 파싱 작업 수행.
- `deque`와 `threading.Lock`을 사용하여 큐 접근의 동시성 문제 원천 차단.

```python
# Thread-Safe Queue Implementation
def put(self, packet):
    with self._lock:
        self._queue.append(packet)
```

### 2. ICD 파싱의 지옥 - 📝 바이트와의 전쟁

ICD(Interface Control Document) 문서는 종이 위에 있었지만, 실제 데이터는 0과 1의 비트스트림이었습니다.
특히 '리틀 엔디안' 처리가 문제였습니다. `struct.unpack`을 사용할 때 포맷 문자열(`<I`, `<H`)을 실수하면 전혀 엉뚱한 값이 나왔습니다.

**해결책**: **Dataclass 기반 모델링**

- 모든 메시지 구조를 Python dataclass로 1:1 매핑.
- 파싱 로직을 `ICDParser` 클래스로 캡슐화하여, 비트 연산 로직을 비즈니스 로직(Processor)과 완전히 분리.

### 3. 지터(Jitter) 계산의 딜레마 - 📉 "변동성"을 정의하라

처음엔 단순히 `현재 도착 시간 - 이전 도착 시간`을 지터라고 생각했습니다. 하지만 이는 '간격(Interval)'이지 '지터(변동성)'가 아니었습니다.
패킷이 0.1초마다 정확히 오면 간격은 0.1초지만 지터는 0이어야 합니다.

**해결책**: **RFC 1889 표준 변형 적용**

- `Jitter = |(Current_Gap) - (Previous_Gap)|`
- 이 공식을 적용하자 그제서야 통신 품질이 불안정할 때만 수치가 튀는 정확한 그래프를 얻을 수 있었습니다.

### 4. 속도 최적화 - � pandas는 만능이 아니다

데이터 분석을 위해 `pandas.DataFrame`을 사용했는데, 실시간으로 행(Row) 하나씩 `append`를 하니 시스템이 점점 느려졌습니다.
DataFrame은 생성 비용이 비싼 자료구조였기 때문입니다.

**해결책**: **하이브리드 저장소**

- 실시간 데이터 수집은 가벼운 `deque` (리스트) 사용.
- 복잡한 통계 분석(ML, 1시간 추이 등)이 필요할 때만 `pd.DataFrame(list(deque))`로 변환.
- 이 방식으로 메모리 사용량 80% 감소, 처리 속도 10배 향상 달성.

## 🤖 ML 도입: 단순 감시를 넘어 '예측'으로

단순한 임계값(Threshold) 기반 알람은 오탐(False Alarm)이 너무 많았습니다. 네트워크 환경마다 '정상'의 기준이 달랐기 때문입니다.

### 왜 'Isolation Forest'인가?

- 지도 학습(Supervised Learning)은 불가했습니다. '비정상' 데이터가 압도적으로 부족했기 때문입니다.
- **비지도 학습(Unsupervised Learning)** 중에서도 고차원 데이터의 이상 탐지에 탁월하고 속도가 빠른 **Isolation Forest**를 선택했습니다.

PPS와 지터뿐만 아니라 가용성, 패킷 손실률 등 8가지 특성(Feature)을 앙상블한 모델을 구축했고, 결과적으로 **단절 5초 전의 미세한 지터 패턴**을 잡아내는 성과를 거뒀습니다.

### 범인은 '객체 참조' (Object Identity)

이틀간의 디버깅 끝에 찾아낸 원인은 너무나 허무했습니다. 초기화 코드의 실수였습니다.

```python
# Bug Scenario
queue_A = PacketQueue()
sniffer = PacketSniffer(queue=queue_A)  # Sniffer는 A에 패킷을 넣음

queue_B = PacketQueue()
processor = PacketProcessor(queue=queue_B) # Processor는 텅 빈 B를 감시함
```

`_init_modules()` 함수에서 객체를 각각 새로 생성해버리는 바람에, 패킷을 넣는 큐와 꺼내는 큐가 서로 다른 인스턴스였던 것입니다.
이 경험은 **DI(의존성 주입) 패턴**의 중요성과 **객체 생명주기 관리**의 필요성을 뼈저리게 느끼게 해주었습니다.
