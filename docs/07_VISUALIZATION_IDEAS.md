## 2. 데이터 분석의 현실적 제약

### 2.1 timestamp 미공개 문제

> **멘토 피드백**: `4f000000`은 timestamp인데 실제 시간이 아닌 0으로 채워져 있음 (비공개)

| 문제 | 영향 | 현재 대응 |
|------|------|----------|
| ICD timestamp 비공개 | 실제 전송/수신 시간 알 수 없음 | `datetime.now()` 사용 |
| Python 시간 정밀도 | ms 단위 정확도 보장 안됨 | 5ms threshold 적용 |
| OS 스케줄링 지연 | 캡처 시점과 실제 도착 시점 차이 | 지터 분석 정확도 제한 |

### 2.2 지터 분석 한계

```
정확한 지터 측정 불가 (파이썬 datetime 한계)
→ 지터 값은 "참고용"으로만 활용
→ 추가 개선 불필요 (멘토 확인)
```

## 4. 데이터 저장 구조 개선 제안

### 4.1 현재: deque 방식

```python
self._records: deque = deque()  # 시계열 저장
```

**문제점**:
- 인덱싱 비효율
- 상관관계 분석 어려움
- 시간대별/msg_code별 그룹핑 어려움

### 4.2 개선안 A: 인덱싱 추가

```python
# 기존 deque + 인덱스 딕셔너리
self._records_by_time: Dict[str, List[PacketRecord]] = {}  # 분 단위
self._records_by_code: Dict[int, deque] = {}  # msg_code별
```

### 4.3 개선안 B: pandas DataFrame (권장)

```python
import pandas as pd

self._df = pd.DataFrame(columns=[
    "timestamp", "sequence", "msg_code", "jitter", "size"
])

# 분석 시
hourly = self._df.resample('H', on='timestamp').mean()
by_code = self._df.groupby('msg_code')['jitter'].mean()
```

**장점**:
- `groupby`, `resample`, `rolling` 분석 기능
- 시각화 라이브러리와 호환
- 파일 저장/로드 용이
