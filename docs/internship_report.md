# 인턴십 활동 결과 보고서

## 1. OJT 활동 내용 (주차별 상세)

### 1주차: 프로젝트 기획 및 현업 이해

- 자율SW팀 현업 업무·조직 구조·개발 프로세스를 파악하고, **UGV-MON(무인지상차량 VIC↔OCS 실시간 통신 모니터링 대시보드)** 프로젝트 목표를 정의함.
- Python 3.9+, Dash, Plotly, Scapy 중심 기술 스택 및 개발환경을 구성하고, **8주 단계별 일정(기획→요구사항→설계→구현→통합→검증)** 을 수립함.
- 수동 감시(제어 패킷 송신 불가), 내부망 Linux 환경 등 **운영 제약 조건**을 반영한 기술 선택을 수행함.

### 2주차: 요구사항 분석 및 구조 설계

- 무기체계 SW 개발 프로세스 및 **체계공학 관점**의 요구사항 도출 방법을 학습함.
- **ICD(인터페이스 통제 문서) 기반** 기능 요구사항을 도출하고, UML 수준의 아키텍처 설계를 진행함.
- **Pipeline(캡처→파싱→저장) / Store / Service / UI** 4개 레이어로 분리된 구조를 확정하고, 단일 책임 원칙(SRP)에 따른 모듈 경계를 설계함.

### 3주차: ICD 분석 및 파서 설계

- **ICD v1.0** 문서를 분석하여 12B 헤더 구조, 체크섬 규칙, 0x01 운용 상태 페이로드(87B) 명세를 파악함.
- Ethernet Frame + UDP 포트 필터(50000↔61000) 기반 **Scapy BPF 필터** 설계를 수행함.
- ICD 파서 설계 및 UI 와이어프레임을 작성하고, **Mock 데이터**를 활용한 초기 UI 검증을 진행함.

### 4주차: 핵심 메시지 분석 기능 구현

- **ICDParser**를 `struct` 모듈로 구현하고, 헤더 파싱·체크섬 검증·운용 상태 페이로드 해석 로직을 완성함.
- **PacketStore**(deque 기반)에 지터(RFC 3550 인접 간격 차이), 패킷 손실(시퀀스 갭 4bit 순환), 가용성(5분 윈도우) 계산 로직을 구현함.
- Live/Mock 모드 전환, 실시간 로그 테이블(AG-Grid) 업데이트 등 **운영에 가까운 기능**을 추가함.

### 5주차: 데이터 분석 기능 확장

- 실시간 리스트 + 필요 시 DataFrame 변환 구조를 적용해 **처리 성능과 분석 유연성**을 확보함.
- **연결 이력**, **운용 상태 전이**, **비상정지 원인별 통계**를 구현하여 운영자가 한 화면에서 전체 상태를 파악할 수 있는 **분석 대시보드**를 완성함.
- 패턴(상태 변경 감지, `_last_*` 비교)을 활용한 **데이터 기반 UI 갱신** 설계를 적용함.

### 6–7주차: ML 이상 탐지 시스템 구현

- **Isolation Forest**(비지도 학습)와 **규칙 기반 탐지**(PPS 급락, 가용성 저하)를 결합한 **앙상블 이상 탐지 시스템**을 설계·구현함.
- **8차원 특성 벡터**(jitter_current, jitter_p95, pps_trend, loss_rate, quality_score 등)를 도메인 지식 기반으로 설계하고, **FeatureExtractor → MLPipeline → MLService** 파이프라인을 구축함.
- **3D 산점도**(지터·PPS·손실률), **이상 점수 타임라인**, **신뢰도 게이지**, **기여 특성 Z-Score 차트** 등 ML 전용 시각화 패널을 Dash UI에 통합함.
- Cold Start 대응으로 **Rule 기반 탐지**를 항상 활성화하고, ML 학습 완료 후 **앙상블 판정(OR)** 으로 최종 이상 여부를 결정하는 구조를 확립함.

### 8주차: SW 통합 검증 및 문서화

- **54개 pytest 테스트**를 통과시켜 단위·통합 검증을 마무리함.
- ruff, mypy, 타입 힌트를 활용한 **코드 품질 관리**를 진행함.
- 8개 문서(docs/) 및 **최종 프로젝트 보고서**를 작성하여 전체 흐름과 설계 의도를 문서화함.

## 5. 기술 하이라이트 (임원면접용 요약)

### 아키텍처

- **4계층 분리**: Pipeline(캡처→파싱→저장) / Store / Service / UI
- **Single Responsibility**: CaptureService(캡처 제어), StatsService(통계), MLService(이상 탐지), DashboardBuilder(Dict 빌드)
- **ServiceProvider**: 4개 서비스를 조율하는 오케스트레이터 역할

### ML 이상 탐지 (상세)

#### 이상 점수 (Anomaly Score)

- **출처**: Isolation Forest `score_samples()` 반환값
- **범위**: -1 ~ 0 (정상→0, 이상→-1에 가까움)
- **의미**: 격리 깊이 기반. 이상치는 적은 분할로 격리되어 점수가 낮음
- **임계값**: `model.offset_` (기본 -0.3). `score < threshold` → 이상

#### 신뢰도 (Confidence)

- **공식**: `sigmoid((threshold - score) / spread)`
- **의미**: "이상으로 판정할 확신의 정도" — 0% 정상, 100% 확실한 이상
- **Rule 전용 시**: ML 미학습이면 Rule 위반 시 50%, 미위반 시 0%

#### 신뢰도 게이지 색상 (초록→노랑→빨강)

| 구간    | 색상 | 의미                   |
| ------- | ---- | ---------------------- |
| 0–30%   | 초록 | 정상/경미한 이상       |
| 30–70%  | 노랑 | 경계 구간, 주의 필요   |
| 70–100% | 빨강 | 확실한 이상, 즉시 확인 |

#### 기여 특성 (Contributing Features)

- Z-score \|z\| > 2.0 인 특성만 상위 3개 표시
- 색상: \|z\| > 3 빨강, > 2 주황, > 1.5 노랑
- Rule 위반 시: jitter_high, pps_low, loss_high, checksum_fail를 z=2.5로 표시

#### Rule 기반 임계값

- 지터 > 50ms, PPS < 50, 손실률 > 5%, 체크섬 실패율 > 10%

#### 앙상블 및 Cold Start

- **비지도 학습**: Isolation Forest (라벨 불필요, O(n) 복잡도)
- **Cold Start 대응**: Rule 기반을 항상 실행, ML 학습(최소 500샘플) 후 앙상블
- **설명 가능성**: Z-score 기반 기여 특성 시각화

### 핵심 KPI (7개)

- 수신 PPS, 파싱 성공률, 체크섬 오류율, 패킷 손실, 가용성(5분), 지터(현재), 지터(P95)
