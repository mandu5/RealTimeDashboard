# 메시지 형식 참고 (포트폴리오 데모용)

> **중요 — 공개 범위에 대한 안내**  
> 이 문서는 **UGV-MON 저장소의 Mock/Live 파서 구현을 설명하기 위한 기술 메모**입니다.  
> 여기 적힌 필드 이름·비트 의미·예시 값은 **교육·포트폴리오용 “합성( synthetic ) 스키마”** 로 두었으며, **특정 회사·프로그램·실제 배포 장비의 공식 ICD(인터페이스 통제 문서)를 대체하거나 복제한 것이 아닙니다.**  
> 실무에서 사용하는 규격서·NDA 자료와 **동일·유사 여부는 독자가 추론할 수 없도록** 구체 식별자(노드 ID 예시 등)와 세부 운용 명칭은 공개 문서 수준에서 생략·일반화했습니다.  
> **법적·계약상 공개 가능 여부는 반드시 소속 조직의 담당 부서에서 별도 확인**하십시오.

---

## 개요

이 저장소의 파서(`ugv_mon/pipeline/icd_parser.py`)는 아래와 같은 **고정 길이 헤더 + 가변 페이로드 + 2바이트 체크섬** 구조를 가정합니다.  
바이트 오프셋·필드 순서는 **코드와 동일**하지만, 아래 “의미” 열은 **데모 UI·지표 설명을 위한 내부 라벨**입니다.

---

## 메시지 전체 레이아웃

```
┌─────────────────────────────────────────────────────────────┐
│              데모용 바이너리 메시지 (합성 스키마)              │
├──────────┬──────────┬──────────┬────────────┬───────┬───────┤
│ TimeStamp│  MSG ID  │ Reserved │ DataLength │ Data  │Chksum │
│ (4 bytes)│ (4 bytes)│ (2 bytes)│ (2 bytes)  │(가변) │(2 B)  │
├──────────┼──────────┼──────────┼────────────┼───────┼───────┤
│ 0-3      │ 4-7      │ 8-9      │ 10-11      │ 12-N  │ 끝 2B │
└──────────┴──────────┴──────────┴────────────┴───────┴───────┘
```

**총 길이**: `12 (헤더) + DataLength + 2 (체크섬)` bytes

---

## 헤더 필드

### 1. TimeStamp (4 bytes, Little Endian)

상위 바이트는 구현에서 **32비트 워드**로 읽고, **하위 4비트만 짧은 시퀀스 번호**로 쓰는 패턴을 사용합니다(손실 추정용).  
정확한 비트 처리는 코드를 기준으로 합니다.

```python
timestamp = struct.unpack('<I', data[0:4])[0]
sequence = data[3] & 0x0F  # 구현 기준: 하위 4비트
```

- 시퀀스는 **0~15 순환**이므로 갭 판정 시 롤오버를 고려해야 합니다.

### 2. MSG ID (4 bytes)

| 바이트 오프셋(헤더 기준) | 의미 (데모)   |
|-------------------------|---------------|
| 4                       | source_id     |
| 5                       | dest_id       |
| 6                       | msg_code      |
| 7                       | ack_flag      |

```python
source_id = data[4]
dest_id = data[5]
msg_code = data[6]
ack_flag = data[7]
```

**공개 문서에서는 구체적인 16진 예시 패킷을 적지 않습니다.**  
테스트·구현에 쓰이는 상수는 `ugv_mon/models.py`, `tests/test_icd_parser.py` 등을 참고하세요.

### 3. Reserved (2 bytes)

예약 필드. 파싱만 하고 비즈니스 로직에는 사용하지 않을 수 있습니다.

### 4. DataLength (2 bytes, Little Endian)

페이로드 길이. 상태류 메시지(`msg_code == 0x01`)는 **이 구현에서** 길이 `87` 바이트를 사용합니다(데모 데이터 생성·테스트와 맞춤).

---

## 페이로드 (상태 보고형, `msg_code == 0x01`)

아래는 **이 저장소가 UI에 넘기는 최소 필드 집합**에 대응하는 요약입니다.  
장치명·모드 라벨은 화면 표시용이며, 실제 장비 명세와 1:1 대응을 주장하지 않습니다.

### 1. 구성품 연결 비트맵 (uint16, LE)

- 16비트 중 하위 비트들이 “서브시스템 연결 여부”를 나타냅니다.  
- 비트→이름 매핑은 `ugv_mon/constants.py`의 `DEVICE_NAMES` 등 **코드 정의**를 따릅니다.

### 2. 플랫폼 상태 바이트 (uint8)

3비트 + 2비트 + 2비트 등으로 **운용 모드 / 권한 / 주행 상태**를 압축해 둔 필드입니다.  
**공개 문서에서는 민감하거나 오해될 수 있는 세부 군사 용어 대신**, 코드 내 `models.py`의 Enum·라벨 테이블을 단일 출처로 두었습니다.

### 3. 이상·정지 관련 워드 (uint16 일부 비트)

상위 비트들에 **여러 종류의 정지·단절·조작 이벤트**를 비트 플래그로 담습니다.  
각 비트의 한글 라벨은 `EMERGENCY_SOURCE_NAMES` 등 **코드에 정의된 데모 라벨**을 기준으로 합니다.

## 체크섬 (데모 구현)

이 저장소의 검증 로직은 **“체크섬 필드를 제외한 모든 바이트 합을 16비트로 마스크”** 하는 방식입니다.

```text
checksum = (모든 바이트 합, 체크섬 2바이트 제외) & 0xFFFF
```

구현: `ugv_mon/pipeline/icd_parser.py` 및 본 문서 이전 버전에 있던 의사코드와 동일한 아이디어입니다.

---

## 파싱 플로우 (요약)

1. 최소 길이: 헤더 + 체크섬 가능 여부 확인  
2. 체크섬 검증  
3. 헤더 필드 순서대로 해석  
4. `12 + DataLength + 2 == len(packet)` 인지 확인  
5. 알려진 `msg_code`만 페이로드 구조체로 해석  

실패 시 동작은 `ParseResult` 및 콜백 쪽 처리를 참고합니다.

## 시퀀스·손실 추정

짧은 시퀀스(4비트) 기준의 갭 계산은 **패킷 저장소**(`ugv_mon/store/packet_store.py`)에서 수행합니다.  
8비트 전체 범위 롤오버 예시가 필요하면 테스트 코드의 시나리오를 참고하세요.

## 문서 역할 정리

| 이 문서가 하는 일 | 이 문서가 하지 않는 일 |
|------------------|------------------------|
| 저장소 안에서 메시지 레이아웃을 **개념적으로** 설명 | 실제 고객사·프로그램의 **공식 ICD** 제공 |
| 공개 시 민감 표현을 줄이기 위한 **주의문·일반화** | 법적 적합성 판단 |

추가로 공개 범위를 더 줄이려면, 본 파일을 더 짧게 줄이고 **“상세 필드는 소스 코드 주석만 유지”** 하는 방식도 가능합니다.
